Full security bảo vệ luồng Taxi – Wallet thế nào?

Alice đồng ý cho Taxi dùng ví. Full security kiểm tra ai đang xin quyền, được làm gì, code/token còn dùng được không trước khi cấp hoặc chấp nhận quyền truy cập.

BÁM VÀO MÃ HIỆN TẠI · HTTP LOCALHOST

Ba thành phần, ba trách nhiệm

Taxi server · bên xin quyền

Đưa Alice sang Wallet đăng nhập, giữ token phía server và chạy job thanh toán.

→
Wallet AS · bên cấp quyền

AS là Authorization Server: xác thực, xin consent, kiểm code và cấp/refresh token.

→
Wallet API · bên giữ ví

Taxi gửi token đến API. API kiểm token và quyền trước khi đọc số dư hoặc charge.

Mật khẩu Wallet chỉ nhập tại AS. Sau consent, browser mang code về Taxi; Taxi đổi code lấy token qua kết nối giữa các server.

Những kiểm tra Full bổ sung so với Baseline

Baseline cố ý bỏ các kiểm tra dưới đây để so sánh. Cùng một request sai, Full sẽ dừng tại bước tương ứng.

01 / ĐÚNG NƠI NHẬN

Khớp chính xác redirect URI

Cơ chế: AS đối chiếu toàn bộ địa chỉ callback với địa chỉ đã đăng ký. Sai thì hiện lỗi tại AS, không chuyển hướng.

Chặn gửi code về website của kẻ tấn công. Địa chỉ gần giống vẫn bị từ chối.

02 / ĐÚNG ỨNG DỤNG

Xác thực client bằng secret

Cơ chế: Taxi gửi client ID và secret bằng HTTP Basic tới /token. AS kiểm secret với bản băm Argon2id đã lưu.

Biết tên taxi-web chưa đủ để mạo danh Taxi. Sai secret → 401 invalid_client. Basic chỉ là cách đóng gói, không mã hóa đường truyền.

03 / CODE CẦN THÊM BẰNG CHỨNG

PKCE S256

Cơ chế: Taxi giữ chuỗi ngẫu nhiên verifier, gửi bản biến đổi challenge = BASE64URL(SHA256(verifier)) khi xin code. Lúc đổi code, AS tính lại từ verifier và so khớp.

Lấy được code vẫn chưa đủ: kẻ lấy trộm còn phải có verifier đúng của lần liên kết đó.

04 / ĐÚNG QUYỀN ĐƯỢC CẤP

Giới hạn scope và grant

Cơ chế: AS kiểm loại luồng được phép dùng (grant) và danh sách quyền (scope). Refresh chỉ giữ hoặc thu hẹp quyền; không tự thêm quyền mới.

taxi-m2m chỉ được xin rates:read. Xin wallet:charge → invalid_scope.

05 / CODE CÓ CHỦ VÀ CÓ HẠN

Gắn code với đúng lần ủy quyền

Cơ chế: Code được gắn với client, callback, user, scope và PKCE challenge. Khi đổi, AS kiểm client/callback/verifier và hạn 60 giây.

Code có trong database vẫn chưa chắc dùng được. Sai binding hoặc hết hạn → invalid_grant.

06 / KHÔNG ĐỔI MỘT CODE HAI LẦN

One-time code + transaction

Cơ chế: Kiểm trạng thái, đánh dấu code đã dùng và lưu thông tin token trong cùng transaction — một lần cập nhật trọn vẹn. Hai request đồng thời chỉ có một request thành công.

Replay code đúng binding làm AS từ chối và thu hồi grant. API tra danh sách thu hồi nên token cũ của grant cũng bị chặn.

07 / REFRESH TOKEN LUÔN THAY MỚI

Rotation + phát hiện dùng lại

Cơ chế: Refresh bằng R1 → cấp R2, đánh dấu R1 đã dùng. Nếu R1 xuất hiện lại với đúng client, AS thu hồi cả family: nhóm token sinh từ cùng lần cấp quyền.

R2 cũng bị vô hiệu sau khi phát hiện reuse. AS kiểm đúng client và hạn tối đa 7 ngày; client khác không được dùng token này.

08 / CHỦ VÍ CÓ THỂ DỪNG QUYỀN

Kiểm consent khi refresh

Cơ chế: Alice gỡ quyền tại AS → consent và refresh family bị đánh dấu revoked. Full kiểm các cờ này trước khi refresh; Taxi nhận lỗi rồi xóa vault của liên kết.

Taxi không thể tiếp tục xin access token mới. Baseline có ghi revoked nhưng cố ý chưa kiểm khi refresh.

Ví dụ dễ quan sát: replay refresh token

R1/R2 dưới đây là nhãn minh họa, không phải token thật.

  1. Taxi dùng R1 → AS trả 200, cấp access token mới và R2.
  2. Kẻ khác dùng lại R1 với credential của đúng client → AS trả 400 invalid_grant, thu hồi family và grant.
  3. Taxi dùng R2 → cũng bị từ chối vì cùng family. Người dùng cần liên kết lại.

Để tránh tự kích hoạt cơ chế này: Taxi xếp hàng refresh theo từng user, không refresh song song và không gửi lại token cũ một cách mù quáng khi mất phản hồi.

Các lớp bảo vệ có sẵn ở cả hai bản

Chúng cũng bảo vệ Full, nhưng không phải phần khác biệt với Baseline.

Biện phápCơ chế và tác dụng
JWT ES256 + JWKSAS ký token bằng private key; API lấy public key từ JWKS đã cấu hình để kiểm chữ ký, issuer, audience và hạn 120 giây. Sửa nội dung token sẽ làm chữ ký sai. Ký không có nghĩa là mã hóa nội dung. Full thêm bước tra grant đã thu hồi.
Scope + principal tại APIAPI kiểm token cho phép hành động nào và đại diện user hay client. Token client vẫn không được charge ví dù có scope charge. Ví được chọn theo sub đã verify, không theo user ID tùy ý trong body.
State + CSRF + sessionstate gắn callback với lần liên kết của browser; Taxi dùng library để tạo/kiểm. Form cần CSRF token gắn session và kiểm Origin khi có. SID đổi sau login; cookie HttpOnly hạn chế JavaScript đọc session, SameSite=Lax giảm gửi cookie trong request từ site khác.
Băm và mã hóa đúng chỗPassword/secret lưu bằng Argon2id. Code/refresh token ngẫu nhiên lưu hash SHA-256 tại AS: so hash thay vì lưu bản gốc. Taxi cần dùng lại token nên lưu bằng AES-256-GCM, với khóa tách khỏi DB, nonce mới mỗi lần và kiểm tính toàn vẹn.
Idempotency + transactionMỗi chuyến có một key. Cùng key và dữ liệu → trả charge cũ, không trừ thêm. Cùng key nhưng dữ liệu khác → 409. Cập nhật số dư và ghi charge trong cùng transaction để tránh xử lý dang dở.
Giảm lỗi từ web và dữ liệuValidate input, SQL có tham số, escape HTML, CSP hạn chế nguồn script và chặn nhúng trang. Login/token có rate limit; form/query từ chối tham số lặp. Log theo trường đã chọn, che code/token/secret; response token có no-store.

Hai tình huống thu hồi có hành vi khác nhau

Alice chủ động gỡ consent: refresh bị chặn, nhưng access token đã cấp vẫn dùng được đến exp ban đầu. Đây là policy của bài; không phải có thêm 120 giây tính từ lúc gỡ quyền.
Phát hiện replay code/refresh: Full ghi grant vào revocation store SQLite. API verify JWT rồi tra store read-only, từ chối token của grant sau khi việc thu hồi đã commit. Nếu không đọc được store, API trả 503 thay vì bỏ qua bước kiểm.
Phạm vi “Full security”: đầy đủ các kiểm tra OAuth đã triển khai trong bài. Ứng dụng dùng HTTP loopback theo yêu cầu, không bảo vệ đường truyền bằng TLS và cookie không có Secure. Diagnostic routes phục vụ quan sát dữ liệu giả. Đây là AS lab một host; chưa có HA, quản lý/rotate khóa production hay kiểm toán bảo mật độc lập.
